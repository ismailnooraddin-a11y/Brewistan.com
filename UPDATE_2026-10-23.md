# Brewistan — 23 October 2026 source update

**Status: source update for review and staging. This is NOT a production certification.**

This is a **full repository root overlay** that preserves the existing Supabase data model,
roles, 3 cafe packages (Classic, Signature, Bespoke), branch-scoped printed URLs, and
separate owner Branding/Campaign/Billing functions. The project is not restarted or replaced.

## What changed

- **Premium compact cards:** the customer PWA wallet uses short, easy-to-scan cards with a cafe mark,
  name, stamp progress, and reward status; the detail view expands into stamp tokens and the independently
  scannable 30-second signed QR. Even Classic gets the same quality of spacing, typography and surfaces;
  plan-locked logo, colour and template rules are unchanged. Flutter's wallet list also has compact cards.
- **Multiple cafe cards:** the PWA wallet follows all server cursor pages rather than stopping after 50.
- **Branch QR:** first-time visitors scanning a cafe/branch URL sign in, complete their profile and get that
  cafe's card; already-signed-in visitors open its card. An in-PWA QR reader can open printed cafe links
  within the installed app, even on iOS. **An external iPhone Camera QR scan cannot be guaranteed to
  launch an installed PWA**; it may open Safari with a separate login session.
- **Login:** owners and customers can choose phone OTP or *existing verified email* OTP, no password.
  Phone registration is preserved. The account setting links an email using Supabase Auth and confirmation,
  without creating an unconnected email-only customer account.
- **Security and correctness:** two additive migrations guard blocked sessions on customer RPCs,
  make cafe/first-branch setup transactional and retry-safe, fix long-name slug boundaries and use
  historical campaign terms for first offline stamps. A new database test tests the session and setup fixes.
- **Scanner:** freeze cafe/branch context for a scanned QR, and reuse the original event UUID when retrying
  an unknown result. Transactions remain barista-confirmed and server-validated.
- **Reliability:** keep a still-valid QR certificate when offline renewal fails, refresh active cards while
  visible, show real banked reward labels and expiry, handle Arabic/Persian digits, distinguish unavailable
  owner reports from zero activity, and reduce OTP fallback deadline conflicts.
- **Native:** preserve clock rollback evidence between restarts, let healthy queue events progress when
  one encrypted row is unreadable, and allow the online server to validate an owner-restored reward.
- **Operational documents:** clarified prelaunch privacy text; earlier audit reports in this archive are
  historical and should not be read as an audit of this updated code.

## Things **not** delivered by this ZIP

Real **Apple Wallet and Google Wallet passes** are NOT implemented. The user-supplied Mr Coffee screenshot
is an OS Wallet example, not a specification that can be forced onto either provider's native pass layout.
Implementing actual passes requires Apple Pass Type certificates, Google Wallet issuer access, signed
pass issuance, platform-specific rendering, update/revocation processing, and a secure design for dynamic
customer QR and rewards. The current cards are inside Brewistan's PWA / Flutter app only.

Other remaining work includes: PWA/browser push subscriptions, browser self-service account deletion,
web device management, storage ownership recovery on account deletion, extensive live-provider testing,
production load profiling, and full accessibility and real-device design review. Native offline and wallet
integration boundaries must be verified on device; the project cannot promise uninterrupted signed-in
sessions when authentication is revoked or browser app data is cleared.

## GitHub Codespaces installation (repository root)

Copy the ZIP into your repository **root**, then run:

```bash
unzip -o brewistan-update-2026-10-23.zip -d . && rm brewistan-update-2026-10-23.zip
python3 scripts/verify-manifest.py
git status --short
```

Review the file changes first. Only when you are ready to run CI and deploy:

```bash
git add -A
git commit -m "Brewistan compact cards, email OTP and PWA reliability fixes"
git push origin main
```

After push, watch **GitHub Actions CI**, **Supabase deployment**, and **Vercel deployment**. If CI fails,
production Supabase changes will not deploy; investigate failures rather than bypassing tests.

### Supabase email OTP prerequisites

Email sign-in is intentionally limited to **existing verified Auth emails** (`shouldCreateUser:false`).
An email entered only in the optional customer profile field is **not** an email login identity.
Sign in by phone, open **Account settings → Link / verify email**, verify the email, then use email OTP.
In Supabase Auth: enable Email, enforce email confirmation, configure a reliable SMTP sender for real
usage, and set the email Magic Link template to include `{{ .Token }}` if you want a six-digit code instead
of a magic-link-only flow. Test email-change confirmations and limits in staging.

### Existing package rules

All three packages and their current admin/owner permissions remain in place. Card compactness and
quality **do not** depend on subscription tier. Classic's current status-based metallic colours remain;
Signature and Bespoke retain their own authorized branding and editor capabilities.
